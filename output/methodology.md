# Methodology

## 1. Summary

All work was done in the Claude Code CLI (model: Claude Fable 5.2). Nothing was typed into this sheet by hand: Claude Code classified the vendors, wrote the scripts that build every tab, and ran the quality checks. Result: 386 vendors, $7,887,359 of spend, $1,764,587 of estimated annual savings (22.4%). Project folder: https://github.com/dimjingles/crossover-vendor-analysis

## 2. Approach

| Step | What was done | Output |
|---|---|---|
| 1. Read the source | Claude Code read the exported vendor list and kept an untouched copy as the input. | data/vendors_source.csv |
| 2. Set department rules | Each vendor is classified by its primary function (the department that normally buys that kind of vendor), using five ordered rules: deal costs to M&A; function-specific tools and services to that function; company-wide software to SaaS; physical workplace to Facilities; everything else to G&A. | Rules in build.py and the README |
| 3. Classify every vendor | Department (from the Config tab), one-line description, action and written rationale. Vendors in the same situation share one rationale template so they are treated consistently. | data/classifications.psv |
| 4. Verify unknowns | 24 web searches on the larger vendors that could not be identified from the name. Vendors still unconfirmed are marked Low confidence, not given an invented description. | prompts/web_searches.md |
| 5. Apply the acquisition lens | Deal advisers and prior-owner fees terminate; back-office vendors consolidate into the parent company; satellite offices close. | Suggestions and Rationale columns |
| 6. Quantify savings | Saving = cost x a stated rate (Terminate 100%, Consolidate 30%, Optimize 10%), with documented exceptions such as 0% for statutory charges and unverified vendors, 20% for audit and legal, 15% for Salesforce. | Est. Annual Savings column |
| 7. Roll up and write | The Top 3 tab and the memo are generated by script; every dollar figure and count is computed from the vendor rows. Wording such as site counts and assumed rates is written by hand. | make_workbook.py |
| 8. Quality-check | Automated checks, an independent AI review, and a blind re-classification of every department (section 5). | output/qc_report.md and review logs |

## 7. Limitations

| Limit | Detail |
|---|---|
| No contracts, invoices or usage data | Everything is inferred from vendor names and 12 months of spend. Savings are estimates to confirm against contracts; exit costs are not netted off. |
| Unidentified vendors | 53 vendors ($324,574, 4.1% of spend) are Low confidence and carry almost no assumed saving. |
| One-off costs | $226,932 of Opportunity 2 is deal and prior-owner cost that ends on its own. |
| Assumptions about the parent company | Back-office savings assume the parent has an auditor, counsel and payroll provider to join. |
